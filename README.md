## 🗄️ Data Format

### Venues (`data/venues.json`)
Each venue is a JSON object:
```json
{
  "id": "1",
  "slug": "lake-palace-udaipur",
  "name": "Lake Palace",
  "country": "India",
  "countryCode": "IN",
  "city": "Udaipur",
  "citySlug": "udaipur",
  "area": "Lake Pichola",
  "type": "Heritage Palace",
  "setting": "Indoor + Outdoor",
  "capacityMin": 100,
  "capacityMax": 1000,
  "priceHint": "₹15L+",
  "image": "/images/udaipur-city.jpg",
  "imageAlt": "Lake Palace Udaipur",
  "shortDescription": "A floating palace on Lake Pichola.",
  "amenities": ["Pool", "Spa"],
  "eventTypes": ["Wedding", "Reception"],
  "featured": true,
  "status": "published",
  "createdAt": "2026-10-01T10:00:00Z",
  "updatedAt": "2026-10-10T10:00:00Z"
}
```

**`status`** controls visibility:
- `"published"` → visible on the public website
- `"draft"` → hidden from public, only visible in admin

### Enquiries (`data/enquiries.json`)
Form submissions from the contact/venue pages. Each enquiry has:
```json
{
  "id": "1",
  "name": "Priya Sharma",
  "phone": "+91 98765 43210",
  "email": "priya@example.com",
  "city": "Udaipur",
  "eventType": "Wedding",
  "eventDate": "December 2025",
  "guestCount": "300-600",
  "message": "Looking for a palace venue near Lake Pichola",
  "venueName": null,
  "source": "website",
  "status": "new",
  "createdAt": "2026-10-28T15:02:53.596Z"
}
```

**`status`** values:
- `"new"` → just submitted, unread
- `"read"` → opened in the inbox
- `"replied"` → you've responded
- `"archived"` → no longer active

```env
# JWT signing secret (for future use)

JWT_EXPIRES_IN=7d

# Cache revalidation secret (must match main website's .env)
REVALIDATE_SECRET=vomp_revalidate_2024

# Main website URL (used to flush cache when content changes)
MAIN_SITE_URL=http://localhost:3100
```

## 🔄 How Live Updates Work

When you **publish, edit, or delete** any content in the admin panel, it automatically:

1. Saves the change to the JSON file in `data/`
2. Sends a `POST http://localhost:3100/api/revalidate` request with the secret header
3. The main website purges its 30-second cache
4. The next visitor to the website sees the updated content immediately

**If you want to manually trigger a refresh:**
- Go to the **Dashboard** in the admin panel
- Scroll down to the Platform section
- Click **"Sync main site"**

## 🔒 Security Notes

1. **Keep `.env.local` private** — it contains your admin password and secrets.
   This file is listed in `.gitignore` and should never be committed.

2. **Change the default password** before making the admin panel accessible on
   a real server. Edit `ADMIN_PASSWORD` in `.env.local`.

3. **The `REVALIDATE_SECRET`** must be the same in both:
   - `Vomp-Admin/.env.local`
   - `MAIN-WEBSITE/main-website/.env`

4. **In production**, serve the admin panel behind a private URL or VPN —
   it should not be publicly accessible at `/admin` on the main domain.

## 🆘 Troubleshooting

### "Invalid credentials" on login
→ Check `.env.local` — make sure `ADMIN_EMAIL` and `ADMIN_PASSWORD` match exactly what you're typing.

### Main website not updating after changes
→ Click "Sync main site" on the Dashboard, or wait up to 30 seconds.
→ Check that `MAIN_SITE_URL` in `.env.local` points to the right port.

### Server crashes on OneDrive
→ The admin panel stores webpack cache in memory when running on OneDrive. If it crashes, restart with `npm run dev` — it recovers automatically.

### Image not showing on main website
→ Make sure the image path starts with `/images/` (local) or `http://localhost:3200/uploads/` (admin upload).
→ Admin-uploaded images are served from port 3200.
